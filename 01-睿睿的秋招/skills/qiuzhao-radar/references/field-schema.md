# 字段与判定规则

## 1. 岗位字段

| 字段 | 说明 |
|-|-|
| company / company_name | 公司全称（显示用） |
| company_id | 公司归一化后的稳定 ID |
| sub_company | 二级单位/研究院/分公司；分组时不能省 |
| title | 岗位名原文 |
| title_norm | 去届别/批次/地点/标点后的岗位名 |
| job_category | 平台职位类别 |
| city | 归一化城市（如“成都”“南京”） |
| location_raw | 平台原始地点（如“四川省 - 成都市”） |
| education | 原始学历要求 |
| education_state | `yes` / `flag` / `no` / `unknown` |
| majors | 平台需求专业原文 |
| major_state | `yes` / `no` / `unknown` |
| headcount / salary | 招聘人数 / 薪资原文 |
| description | JD 摘要（平台列表自带） |
| grad_year | 2027 / 2026 / … / 空 |
| job_type | 校招 / 实习 / 社招 / 未标注 |
| deadline | 截止日期；没有则空，不猜 |
| base_hit | 城市是否命中目标 base |
| is_operation | 是否一线操作岗 |
| recommendation | 可投 / 待核实 / 异地 / 不推荐 |
| reasons | 判定原因列表 |
| source / source_type | `scbdc` / `sicau` / `ncss` / `iguopin`；平台/学校官方 |
| source_job_id | 来源内唯一 ID |
| url / apply_url | 详情页 / 投递入口 |
| verification_status | `platform_verified`（川e就/NCSS/国聘）/ `school_verified`（川农）/ `unverified` |
| first_seen / last_seen | 首次/最近发现日期 |
| status | `active` / `closed`；用户可扩展 ignored/applied |
| sources | 所有来源链接（JSON） |

## 2. 事件字段

招聘公告、宣讲会、招聘会统一存 `events`：

| 字段 | 说明 |
|-|-|
| event_type | `campus`（招聘公告）/ `teachin`（宣讲会）/ `jobfair`（招聘会/双选会） |
| school | 学校 |
| title | 公告/活动标题 |
| company | 关联公司（公告里有则填） |
| organizer | 举办单位/学校 |
| event_date | 举办/发布日期 |
| deadline | 报名截止 |
| location | 地点（宣讲会/招聘会） |
| url | 详情页 |

**活动不是岗位。** 宣讲会/招聘会单独列，不混进“可投岗位”数量；除非活动页里明确列了岗位并有投递入口。

## 3. 判定顺序

```
硬门槛（任一命中 -> 不推荐）
  ├─ 实习岗（配置 include_internships=false）
  ├─ 社招（include_social=false）
  ├─ 届别 < 2027
  ├─ 学历要求大专/博士
  ├─ 一线操作岗
  └─ 截止日期已过

未知项（任一命中 -> 待核实）
  ├─ 届别未注明
  ├─ 学历口径不明
  ├─ 专业未注明/未命中
  ├─ 校招/社招未标注
  └─ 地点未注明

异地（基础条件明确，但城市不在目标 base） -> 异地
全部明确且通过 -> 可投
```

### 学历

- 硕士/研究生 -> `yes`
- 本科 -> `flag`，保留并提示“硕士是否可投需确认”
- 大专/专科 -> `no`
- 博士 -> `no`（除非岗位写“硕士及以上”）
- 空/不限 -> `unknown`

### 专业

用 **平台专业字段 ∪ 岗位名 ∪ JD 正文** 命中白名单。原因：平台专业字段经常写少或写占位符（如实测“详见职位描述”）。

白名单在 `config.majors` 与 `normalize.DEFAULT_CONFIG`：

- 化工：化学工程与技术、化学工程与工艺、化学工程、化学、应用化学、应用化工技术、化工技术、精细化工技术
- 材料：材料与化工、材料科学与工程、材料化学、材料物理与化学、高分子材料、高分子材料与工程、复合材料与工程、新能源材料
- 相关：环境科学与工程、安全科学与工程、能源动力、能源化学工程、资源循环科学与工程、冶金工程
- 不限：不限专业、专业不限

命中不代表岗位一定合适：采购/销售/项目管理也可能写“材料类”，必须读 JD 判断岗位实质。

### 城市

- `normalize_city()` 把“四川省 - 成都市”归一为“成都”。
- 目标城市默认成都、南京。
- **不做硬过滤**；异地单独列。
- 城市不明 -> 待核实。

### 一线操作岗

只认明确的 `操作工/普工/技工/生产操作员/一线操作/车间操作` 或类别 `化学操作/化工操作员`。不要手写大而全的工种词表；不确定的交给用户复核。

## 4. 各来源字段差异

| 来源 | 强项 | 缺什么 |
|-|-|-|
| 川e就 | 学校公告/宣讲会/招聘会；职位自带 JD 摘要 | 不是企业 ATS；届别/校招属性经常不写 |
| 川农大 | 学校宣讲会/招聘会，结构稳定 | 只有川农一家的数据 |
| NCSS | 全国校招、单位性质、学历、专业字段 | 无截止时间、通常无 JD；专业经常为空 |
| 国聘 | 央企、JD/截止时间/单位性质较全 | 公开推荐池只有约 400 条；完整搜索需登录态 |

> 宽口径池子（NCSS/国聘）会先按 `topic_keywords` / `strong_topic_keywords` 预过滤；过滤数在日报「数据源健康」里显示。

## 5. 日报标签

| 标签 | 含义 |
|-|-|
| 可投 | 硬门槛通过，届别/学历/专业/地点/校招属性都明确 |
| 待核实 | 至少一个关键字段不明，或专业未命中但仍在候选池 |
| 异地 | 其他条件明确，仅城市不是目标 base |
| 不推荐 | 明确违反硬门槛（实习/社招/届别/学历/操作岗/过期） |

日报末尾必须给出排除统计，不能只列可投。

## 5. 飞书输出字段（已接）

### 公司级投递记录

- Base：简历投递记录
- 链接：https://ncnmmj6cf0ef.feishu.cn/wiki/Ec98wjsfuifnEgk1gtbcbiWMn0c?table=tblPKAEr1fsJ3oSm&view=vewcGLAIyD
- 表：`投递记录`（`tblPKAEr1fsJ3oSm`）
- **一行一个公司**；岗位只作为备注里的线索。
- 当前字段：岗位名称、公司、公司类型、城市（多选）、备注、投递状态、岗位链接、截止日期、优先级、建档节点、投递日期。
- 写入映射：
  - **岗位名称：不写**（投递后再填）
  - 公司 ← company_name
  - 公司类型 ← 自动归并（央国企/民企/外企/研究所/公务员/事业编/其他）
  - 城市 ← 公司下所有岗位城市并集，多选：南京 / 成都 / 其他
  - 备注 ← 发现岗位数、可投/待核实/异地/不推荐数量、城市、来源、岗位ID、主要判定、截止
  - 投递状态 ← 待投
  - 岗位链接 ← 公司最常用的招聘入口
  - 截止日期 ← 公司岗位中最早截止
  - 优先级 ← 有可投→首选，否则待核实→备选，否则→降级
- 去重：本地 `feishu_company_synced` + 表内已有公司名；已有公司不重复建行，也不覆盖你的投递状态和备注。
- 公司下所有岗位都不推荐时不写入。
- 当前表没有「二级单位 / 下一步」列，写进备注。

### 日报

- 本地 `~/.qiuzhao-radar/reports/YYYY-MM-DD.md`；飞书只写「投递记录」表，不单独建日报文档。

**写入前先对齐字段名**；`lark-cli base +record-batch-create` 只接受已存在的可写字段。
