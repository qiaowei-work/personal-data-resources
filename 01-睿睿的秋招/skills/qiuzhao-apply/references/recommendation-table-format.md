# 岗位推荐表格式规范

## 总体结构

```
# <公司名> · <年份> 秋招岗位推荐表

| 文档信息 | |   ← 目标base / 数据来源 / 匹配依据 / 生成时间 / 最近更新 / 数据抓取时间
## 摘要              ← 总数 / 纳入 / base命中 / 异地Top3 / 排除 / 某base为0的警示
### ⚠️ 筛选方法及其局限（必读）
### 复核状态
## 一、base 命中（<城市>）
## 二、异地 · Top 3
## 三、排除说明
## 四、岗位详情（仅「首选 / 次选」）
## 五、变更记录
```

---

## 逐节规范

### 文档信息

必须含**生成时间**和**最近更新时间**两个字段——表会持续更新，靠这两个字段判断新鲜度。

### 摘要

| 项 | 数量 |
|-|-|
| 岗位总数 | |
| 纳入候选 | |
| **base 命中（<城市>）** | |
| 异地 · Top 3（候选 N 个）| 3 |
| 排除 | |
| **<城市> base 岗位** | **0** ⚠️ |

若目标 base 之一为 0 岗位，**必须显式警示**并说明"非遗漏、非筛选所致"，避免用户误以为筛掉了。

### ⚠️ 筛选方法及其局限（必读）

固定写清：

- 纳入判定 = 平台专业字段命中 ∪ JD 正文命中关键词，取并集
- 已发现的字段缺陷（专业字段写少 / 类别字段"不限职位"）
- 一句硬话：**表中分档仅代表"专业要求命中"，不代表岗位适配度已核实**

这一节不可省。目的是防止用户看到漂亮的分档以为已代为审核。

### 复核状态

| 标记 | 含义 |
|-|-|
| ✅ 已读 JD · 推荐 | 已读正文，确认岗位实质与专业要求相符，可投 |
| ❌ 已读 JD · 不推荐 | 已读正文，**实际工作内容与求职方向不符** |
| ⏳ 未复核 | 仅字段+关键词粗筛，**岗位实质尚未核实** |

三档缺一不可。只有两档（复核/未复核）时，"读过但否决"会和"没读过"混在一起。

### 一、base 命中

| 优先级 | 岗位 | 单位 | 地点 | 学历要求 | 招 | 截止 | 状态 | 复核 | 一句话理由 | 链接 |
|-|-|-|-|-|-|-|-|-|-|-|

优先级 5 档：**首选 / 次选 / 备选 / 降级 / 不推荐**

- 首选 — 技能直接对口，强烈建议投
- 次选 — 专业对口但职责方向略有偏差
- 备选 — 能投，但方向或条件有不确定性
- 降级 — 专业能过但**实际职责与求职方向不符**
- 不推荐 — 能投但明显不该投（如销售岗）

**「一句话理由」必须控制在 15 字以内**，例如：

| 优先级 | 一句话理由 |
|-|-|
| 首选 | 中试工艺对口·硕士优先 |
| 次选 | 硕士岗位·偏产业研究 |
| 降级 | ❌ 实为工程项目管理 |
| 不推荐 | ❌ 销售岗 |

**Why:** 表格有 11 列，列宽被压缩。理由写长会把整行撑成十几行，表格松散到没法扫读。实测在飞书里渲染出来就是这样。

**详细理由写在「岗位详情」区**，表格只放结论。

### 二、异地 · Top 3

- 排序依据：对口分升序，同分按招聘人数降序
- **只列 3 个**，并写明"异地候选共 N 个"
- **专业要求完整列出，不截断**——截断会导致用户无法复核排序依据（实测：中铝郑州岗的"化学工程与技术类"排在第 7 位，被截断后看不出为何排第一）
- 全表标 ⏳ 未复核（异地岗位通常未读 JD）

### 三、排除说明

```
总 N → 纳入 M，排除 K
  ├─ 学历不符（大专/博士）        N
  ├─ 专业未命中（字段与正文均无）   N
  ├─ 一线操作岗                  N
  └─ 职能岗（采购/销售/市场/人力等） N
```

若某目标 base 为 0 岗位，单独一行说明。

### 四、岗位详情

分三段，**覆盖全部推荐岗位**（不能只写首选/次选，否则备选/降级/不推荐的详细理由无处安放）：

```
### A. 首选 / 次选
    逐个：基本信息 + 链接 + JD 原文（代码块，原样粘贴）+ 详细推荐理由

### B. 其余 base 命中岗位（备选 / 降级 / 不推荐）
    逐个：一句话定位 + 详细推荐理由（**不铺 JD**，给链接）

### C. 异地 Top 3
    逐个：详细推荐理由（**不铺 JD**，给链接）+ 明确标注 ⏳ 未复核
```

**JD 原文只铺「首选 / 次选」**，其余给链接。

理由：全铺会让文档膨胀到几万字，用户不会读；但首选的 JD 必须摆在眼前，因为岗位名会骗人。

**详细推荐理由要写清三件事：**

1. **职责实际是什么**（读 JD 得出的，不是岗位名）
2. **命中/落空了哪些条件**（逐条对标专业、学历、技能、经历）
3. **结论与落差**——能投但方向偏的，必须明说偏在哪

例：

> **职责**：晶体生长、高纯提纯、MO 源合成等中试工艺管理；执行实验方案、数据整理分析、编写 SOP 及工艺规范。
> **对标**：硕士课题即实验设计 + 数据分析（DFT、原位光谱/质谱），有科研报告与专利撰写经历 —— 技能链与岗位职责高度重合。JD 明写「硕士研究生及以上学历者优先」。
> **结论**：本批次最对口的一个。学历要求标"本科"但实际偏好硕士。

### 五、变更记录

| 日期 | 变更 | 说明 |
|-|-|-|

表会持续更新，每次改动留痕：新增岗位、岗位下线、截止日期变动、用户标记投递状态等。

## 链接规范

尽量给出**单岗位直达链接**。若站点无直达 URL（点"查看"只弹窗不跳转），到页面里点一次并观察是否新开标签页，从新标签页的 URL 反推规律。

实测：国聘系点"查看"会新开 `https://www.iguopin.com/job/detail?id=<job_id>`，规律稳定。

**给出链接前必须验证至少 2 个岗位的 URL，确认标题与岗位名一致。**
