# 招聘站点适配

## 通用方法：先找接口，再谈抓取

**优先级：页面自身的 XHR 接口 ≫ DOM 抓取。**

步骤：

1. 用 `list_network_requests`（resourceTypes: `xhr`/`fetch`）看页面调了什么接口
   - 注意：页面若在 MCP 接管前就加载完，日志是空的 → **先 reload 一次再抓**
2. 用 `get_network_request` 看请求体和响应体结构
3. 记录固定参数（project_id / company_id / 站点标识等）和分页参数
4. 在页面上下文执行 `fetch`（同源可绕 CORS）分页拉全量
5. 存原始 JSON，**务必保留 JD 正文字段**（后续读 JD 复核要用）

**为什么优于 DOM 抓取**：不受分页 UI 限制、字段完整、快十倍以上。中铝案例中 DOM 只能看到 20 条/页共 28 页，接口一次拿全 559 条。

找不到接口时退化为 DOM 抓取；再不行请用户手工粘贴。

## 国聘系（iguopin.com）

**已验证**。中铝 2027 校招（`chinalco2027.iguopin.com`）走这套。

### 列表接口

```
POST https://gp-api.iguopin.com/api/jobs/v1/project-job
```

**请求头**（缺一不可）：

```
content-type: application/json
device: pc
subsite: iguopin
version: 5.0.0
```

**请求体**：

```json
{
  "page": 1,
  "page_size": 100,
  "source": "s_job_list",
  "company_id_with_sub": "<从页面抓包获取>",
  "project_id": ["<从页面抓包获取>"]
}
```

`company_id_with_sub` 和 `project_id` 因公司而异，必须从页面抓包取得，不能硬编码。

`page_size` 可设 100，实测有效。

### 响应字段

`data.list[]`，关键字段：

| 字段 | 说明 |
|-|-|
| `job_id` | 岗位唯一 ID，用于拼接详情链接 |
| `job_name` | 岗位名 |
| `company_name` | 一级单位 |
| `department_cn` | 二级单位/部门 ⚠️ 中铝案例中大量为空，注意核对 |
| `education_cn` | 学历要求 |
| `amount` | 招聘人数 |
| `major_cn[]` | 专业类目数组 ⚠️ **可能不完整，见下方警告** |
| `category_cn` | 岗位类别 ⚠️ **经常是"不限职位"** |
| `district_list[].area_cn` | 地点 |
| `end_time` | 截止时间 |
| `contents` | **JD 全文**（职责描述 + 任职要求）|
| `recruitment_type_cn` | "校园招聘" |
| `experience_cn` | "应届生" |

### 岗位详情链接

```
https://www.iguopin.com/job/detail?id=<job_id>
```

点列表页的"查看"按钮会新开标签页跳到这里。已验证 3 个岗位标题精确匹配。

### ⚠️ 本接口的两个字段陷阱（实测）

1. **`major_cn` 可能写少**
   - 「研发工程师｜云南驰宏国际锗业」→ 字段仅 `["冶金工程类"]`，JD 正文却是"冶金工程类、**化学类、化工与制药类、材料类**、仪器类"
   - 「教师｜山东铝业」→ 字段为 `["详见职位描述"]`（占位符）
   - **对策**：纳入判定必须取「字段 ∪ JD 正文关键词」的并集

2. **`category_cn` 不可靠**
   - 559 个岗位中 83 个类别是"不限职位"
   - 导致「采购工程师」「市场营销管理工程师」等职能岗无法靠类别识别
   - **对策**：类别字段 + 岗位名双重兜底，仍不确定的标 ⏳ 交人工

### 其他

- 全部 559 个岗位的 `recruitment_type_cn` 均为"校园招聘"、`experience_cn` 均为"应届生"，无一例外 → 该站点此页面为纯校招，不混社招
- 字段 `is_graduates` 含义不明（58 个 True），**不要用它做判断**

### 表单填写（个人中心简历）

**已验证**（2026-10-08）。通用手法见 `form-filling.md`，以下是本站点特有部分。

**入口**：`https://c.iguopin.com/resume` —— 「我的简历」个人中心。

**板块结构**（各自独立保存，互不影响）：

```
基本信息（必填）· 求职意向（必填）· 教育经历（必填）· 工作/实习经历（必填）
项目经历 · 资格证书 · 自我评价（必填）· 附件
自定义添加：语言能力 / 培训经历 / 荣誉奖励 / 家庭成员 / 实践活动 / 校内职务
```

右侧「简历目录」实时显示各板块是否打勾 —— **这是最省事的完成度检查口**。

**可重复板块**（教育经历 / 工作实习 / 项目经历 / 实践活动）：由「添加」按钮建新条目，
每条单独保存一次。**注意用文档顺序定位「添加」按钮** —— 页面各板块的
`getBoundingClientRect().top` 不可靠（板块在固定高度容器内滚动），按坐标挑按钮会点错板块。
可靠做法：把 `h2` 和「添加」按钮按 `compareDocumentPosition` 排序，取 `h2` 之后最近的按钮。

**特有交互：**

| 字段 | 交互 |
|-|-|
| 籍贯 / 生源地 / 现居住地 / 户口所在地 | 三级级联弹窗，点叶子自动完成 |
| 学校名称 / 专业分类 / 专业名称 | 可搜索 select，需先写关键词触发异步搜索 |
| 期望行业 | **多选级联，上限 3 个**，需点「确定」 |
| 期望职位 / 工作地区 | **单选**（`.ant-select-single`） |
| 就读年月 / 起止时间 / 在职时间 | antd MonthPicker；**开始与结束是两个独立 picker**，必须都填 |
| 工作时间 | 「税前月薪」必填，**单位是千元** |
| 资格证书 | 弹窗，点「编辑」打开；分类 → 子类 → 具体证书三级 |

**本站点已实测的字段陷阱：**

- **起止时间没有「至今」** —— 平台强制校验结束时间，进行中的经历必须填预计结束
- **期望职位的一级分类里没有具体岗位名**，最接近的是「生产制造/营运管理 → 化工」；
  再下面才是「化工研发工程师 / 合成工程师 / 化验检验」等
- **「单位性质」没有「政府机关」** —— 政府单位经历只能归到「事业单位」或换板块
- **「目前行业」没有「在校学生」** —— 在读生只能选相近行业
- **「专业排名」只有区间**（前 5% / 前 10% / …），没有具体名次
- **「自我评价」的关键词是软标签**（形象好气质佳 / 能出差 / 诚实守信…），
  录入技术类关键词不生效，会弹出这组推荐词
